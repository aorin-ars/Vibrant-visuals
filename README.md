# 統合版（Bedrock）: VYSE-Vibrant Visuals

Java版の影mod **Complementary Shaders（Unbound スタイル）** の画作りを、統合版の
Vibrant Visuals で再現するリソースパックです。

## 必要なもの

- Minecraft 統合版 **1.26.0 以降**
- ビデオ設定で **Vibrant Visuals が有効**になっていること

## 導入

1. `VYSE-Vibrant-Visuals-*.mcpack` をタップ／ダブルクリックして開く（自動でインポートされます）
2. **設定 → ビデオ → Vibrant Visuals** を **オン**にする
3. ワールドの **設定 → リソースパック** でこのパックを有効にする

**PBR 追加パック（任意）**: **VYSE-Vibrant Visuals PBR**（`VYSE-Vibrant-Visuals-PBR-*.mcpack`）を
VYSE-Vibrant Visuals の**上**に置いて一緒に有効にすると、ブロックの質感が変わります。

| | 中身 |
|---|---|
| 凹凸 | **ほぼ全ブロック**に凹凸。ブロックのテクスチャ 1,221 枚（葉・草花・作物・ガラス・扉・レール・アニメーションするブロックも含む）にハイトマップ、チェスト・ベッド・シュルカーボックス・鐘・頭・看板・エンチャント台の本の 79 枚に法線マップ（Complementary の「Generated Normals」相当。こちらはブロックの半分の強さにして、作られた物らしいなめらかな面に木目などがうっすら出る程度）。丸石・鉱石・レンガは強く、木材は中くらい、羊毛はほぼ平ら、コンクリートなど模様の無い平らなブロックは凹凸なし（ハイトマップがあるとブロックの境目に細い格子線が出て、平らなブロックでは目立つため）、葉や草花はやや控えめ、ガラスはわずか。すき間は少しざらつかせ、出っ張りとの質感の差を付ける。凹凸を付けないのは水・溶岩（バニラの凹凸をそのまま）・火・ポータル・泡の柱だけ |
| 発光 | グロウストーン・シーランタン・フロッグライト・シュルームライト・マグマなど 40 種を、光源らしく強く光らせる（バニラは例えばグロウストーンで 255 中 41 と弱い）。**鉱石の鉱物部分がほんのり光る**（ダイヤ・エメラルド・ラピス・レッドストーン・金・鉄・銅・ネザー金・クォーツ。石炭は光らない）＝ Complementary の「Glowing Ores」 |
| つや | 氷・金属ブロック・宝石ブロック・黒曜石・彩釉テラコッタ・磨かれた石・鐘・銅のチェストを滑らかにして、映り込みが出るように。宝石の鉱石は鉱物部分だけつやつや |
| 光を通すガラス | **色付きガラス（ブロック・板、黒以外の 15 色）が光を通し、日が後ろから当たるとその色に光って見える**（ステンドグラスの窓や天窓）。バニラのガラスは光をまったく通さない設定。ただし、ガラスを通った日差しが床や壁を青く染めることはできない（Vibrant Visuals の影には色が無く、設定もないため） |
| 雨で濡れる | **Mob・ボート・トロッコ・防具立てなどのエンティティが、雨に当たっている間と水の中にいる間だけ少し暗く、つやつやになる**（粗さが半分ほどに下がり、映り込みとハイライトが出る）。屋根の下に入ったり水から出たりするとすぐ乾く。バニラのエンティティ 172 種が対象（プレイヤーはスキンなので対象外）。アドオンのエンティティ（列車など）には効かない |

Vibrant Visuals では、ブロックの質感（テクスチャセット）が参照する画像は**同じパックの中に**
なければならないため、この追加パックにはバニラのブロックの画像が入ります。そのため
リポジトリには入れず、手元のバニラのファイルから作っています（[作り方](#開発)）。
**個人利用のみ**で、再配布はしないでください。

手動で入れる場合は、zip を展開して `com.mojang/resource_packs/` に置いてください。

## 何が変わるか

| | バニラの Vibrant Visuals | VYSE-Vibrant Visuals |
|---|---|---|
| 画の質感 | 「generic」トーンマップ | **ACES（映画風）トーンマップ**。暗部は締まり、中間調は色濃く、明るい空や夕日はなめらかに白へ抜ける。標準の Vibrant Visuals とは画の系統から変わる |
| 日差し | 白っぽく、夕方は早めに暗くなる | 正午は**澄んだ白**でバニラと同じ 100（125 では明るい壁や空が白飛びしたため）。日向と日陰の差は空の光を絞って付ける。日が低くなると金色、地平線でオレンジから赤 |
| 時間帯の空 | 控えめ | 夕日・朝日は赤く暗くならず、金色からオレンジの光で地面を暖かく照らす。早朝（マゼンタからオレンジ金）→ 朝（青空に暖かいクリーム色の地平線）→ 昼（青空から白っぽい淡い青の地平線）→ 夕方（金色から桃色の地平線）→ 日没（上空はラベンダー、地平線はコーラルピンク。Complementary の夕焼けのように空全体がパステル調）→ 夜（紺色）→ 深夜（濃紺）。真っ黒にはしない |
| 空 | 一面ほぼ同じ青（レイリー散乱 10） | レイリー散乱を 1.3 に下げ、天頂の青から地平線の淡い色へ本物のグラデーションに。太陽のまわりには**小さな光の輪**が集まり、バニラのように空全体が白くかすまない。夜は月にも淡い光の輪 |
| 影 | 灰色（空からの光 100%） | 空からの光を 60% に絞り、日向と日陰の差をはっきり。影は黒く潰れず青みがかったグレー。短い影（正午の太陽は高さ 78°）。夕方は空の光を増やし、色づいた空の光で満たす |
| 夜 | 月明かり 0.4 | 宵のうちは**月明かり 0.6** の青い光で、照らされた面が青く浮かび、谷の霞が青く光る。**深夜は現実の夜のように暗く**、月明かりは 0.2（バニラの半分）、空からの光も弱まり、夜空は黒に近い紺に。形がかすかな青灰色に見え、日陰はほぼ黒。松明などのブロックの光は弱めないので、闇の中でくっきり灯る |
| 空気 | 一部のバイオームだけ一様な霧 | **澄んだ空気感**。遠くの地形が白くぼやけず青くかすみ、谷や洞窟に溜まる（低い所ほど濃く、高度 170 前後で消える）。夕方は金色、夜は月明かりで青く光る。木漏れ日や洞窟の入口からの**光の筋は太陽の方を向いていなくても見える**（太陽が画面の外や木の陰でも、光の向きで筋ができる所には出る）。湿った森・沼・サバンナは濃いめ、砂漠は薄め。ネザーには霞を入れない |
| 雨 | 暗い灰色の霧 | **しっとりした霧雨の空気**。明るい青みがかった灰色のもやが数十ブロック先から景色をやわらげ、遠くの木は灰色の影になって霧に溶ける（描画距離の 6 % から濃くなり、62 % で見えなくなる）。霞も山の上まで濃くなる。雨粒の水しぶきはゲーム標準の小さな青い粒 |
| 水 | 波なし・昔の水の模様 | **透明な水**。水に何も混ぜず（植物プランクトン・泥なし）、水面の不透明度もバニラより下げたので、底や水草が透けて見える。バニラの水の模様（白い筋）と凹凸マップを外し、小さなさざ波だけにしたので、空や岸がきれいに映る。バイオームの水の色がほんのり混ざる |
| 水中 | — | ゲーム標準のまま（以前入れていた水中の霧は、自分の影が黒い影として映り込むため外しました） |
| ブロックの光 | 一律の色 | **色付き**: 松明・炎は橙、魂の炎は水色、レッドストーンは赤、紫水晶・エンダー系は紫、シーランタンは水色がかった白、エンドロッドは青みのある白 など 122 種。光ブロック（見えない光源）は蛍光灯のような白（#EEF4FF）で、車内や駅の照明に合う |
| 太陽・月 | 四角 | **小さな丸い太陽**（幅はバニラの四角の 1/6。光の輪は空の散乱で付く）と**小さな丸い月**（クレーター付き、8 つの満ち欠け） |
| 雲 | 四角い雲の板 | **空一面に描いたふわふわの晴天の雲**（白いかたまりと青空のすき間。ふちは薄くちぎれ、地平線に近いほど小さく密に。スカイボックス）。夕方は日の色に染まる。[下を参照](#空の雲スカイボックス) |
| 色調 | コントラスト 1.15 / 彩度 1.05 | ACES の上に、コントラスト 1.10 / 彩度 1.10（明るさの上乗せはなし。白飛びを避けるため）、色温度をわずかに青寄り（6100 K）。Complementary の昼のような、すっきり少し青みのある色（葉は黄緑ではなく青緑寄り）。暗部はわずかに青く、明部はわずかに暖かく（明るくはせず色だけ） |

### すべてのバイオームに効かせている理由

統合版 1.21.90 以降、ジャングル・砂漠・タイガ・メサ・ネザー・エンドなど多くのバイオームは
**バイオーム専用の照明・大気・色調設定**を持っていて、それが `lighting/global.json` などの
全体設定より優先されます。全体設定だけを書き換えるパックは、平原や森でしか効きません。

このパックは、バニラのバイオームが参照している識別子（照明 15・大気 17・色調 14・水 1）を
**すべて同じ名前で上書き**しています。どのバイオームにいても同じ画作りになり、その上で
砂漠は少し暖かく、雪原は少し白く、といった差を付けています。

## 空の雲（スカイボックス）

統合版は、6 枚の画像（`textures/environment/overworld_cubemap/cubemap_0〜5.png`）で
オーバーワールドの空を描き替えられます。1.21.130 からは Vibrant Visuals でもその画像が
太陽や空の光で照らされるようになりました（`cubemaps/default_cubemap.json`）。

このパックはこの仕組みで、**背景が透明な雲の画像**を空に貼っています。雲以外の部分からは
いつもの Vibrant Visuals の空が見えるので、空の色・夕焼け・夜はそのまま時間で変わり、
雲だけが日の色（昼は白、夕方は金色からピンク、夜は暗い灰青色の影）に照らされます。雨の日は
ゲームが日差しを弱めて空を灰色にするので、雲もそれに合わせて灰色に沈み、空全体が一面の
曇り空に見えます（雲の量そのものは画像なので天気では変わりません）。

雲は**パックの設定で選べます**。ワールドの設定 → リソースパック → 有効にした
VYSE-Vibrant Visuals をタップ → 歯車（⚙）から切り替えてください。

| 選択肢 | 中身 | バニラの雲 |
|---|---|---|
| **Sky: soft clouds**（初期設定） | ふわふわの晴天の雲 | **自動で消えます**（四角い板の雲は表示されません） |
| Sky: soft clouds + the game's clouds | 同じ雲 | オンのままでよい（影を落とすバニラの雲と組み合わせる用） |
| Sky: no clouds | 何も貼らない | お好みで |

知っておいてほしいこと:

- 描いた雲なので**動きません**（空に固定されています）
- 遠くの雲は画像の中で淡い青に溶かしてあります（ゲームの霞をかけると低い雲が消えてしまったため）
- 効くのはオーバーワールドだけです（ネザーとエンドは変わりません）

画像の並び（0〜3 が左から右へ並ぶ側面、4 が上、5 が下）は、実際に動いている
スカイボックス数個の画像の境目を突き合わせて確認しました。

**ゲームの目の高さは、立方体の真ん中ではありません。** 6 枚は普通の立方体として貼られて
いますが、目は立方体の中心より幅の半分の 0.40 倍だけ下にあります。そのため目の高さ
（地平線）は側面の画像の真ん中ではなく**上から 70 % の行**にあたり、側面の真ん中の行は
地平線から約 22° 上に、上の画像は 45〜55° より上だけに見えます。

これは実機のスクリーンショット 2 枚から割り出しました。側面の画像の真ん中の行が空の中に
直線として写り、立方体の角で折れ曲がるので、その消失点から視野角と目の高さが決まります。
公開されているスカイボックスが地平線を側面の画像の上から 70 % に描いていることとも一致します。
雲はこの位置関係に合わせて 1 ピクセルずつ描いているので、ゲーム内で正しい大きさと間隔に
見えます（`tools/draw_sky.py` の `EYE_BELOW_CENTRE`）。以前の 2 つの版はここを誤っていて、
立方体の中心に目があるとして描いた版は雲が頭上の四角の中にしか出ず、平たい箱として描いた版は
雲が縦に引き伸ばされ、地平線の下に鏡写しの雲が見えていました。

雲そのものは、地球の丸みに沿って曲がった雲の層に描いた晴天の雲です。大きなかたまりと
青空のすき間、かたまりの中の小さな房、ちぎれたふちの 3 つの大きさのノイズを重ね、ふちは
薄く透けて中心は白く詰まるようにしています。風の向きにわずかに並びますが、筋や渦のような
目立つ模様は作らないので、どの方向を見ても自然に見えます（前の版の巻雲は、筋がすべて
地平線の一点に集まって渦のように見えていました）。どの面も同じ一続きの雲の層から描くので
面の境目に継ぎ目はありません。写真は使わず、すべて計算で描いています。太陽の向きは
焼き込んでいません（本物の太陽は動くため）。日の色はゲームが加えます。

## Complementary との違い（リソースパックではできないこと）

Vibrant Visuals の見た目はエンジンのシェーダーが決めていて、リソースパックが変えられるのは
**数値の設定とテクスチャだけ**です。Complementary の次の機能は再現できません。

- 草や葉が風で揺れる
- **動く**立体的な雲・オーロラ・星雲（雲は上のとおり、空に描いた止まった雲なら可能）
- 雨で地面そのものが濡れて反射すること（ブロックのつやはテクスチャで決まり、天気では変えられないため。エンティティは描画の切り替えで濡らせるので、PBR 追加パックで対応）
- 雨の日だけ空を曇らせたり、光を弱めたりすること（照明と空の設定は天気で切り替えられません。雨の日の曇り空はゲーム側の処理です）
- 被写界深度・モーションブラー・レンズフレア

時間帯で霞の濃さを変えることもできません（霧の設定はキーフレームに対応していないため）。

## エンティティの影について

**エンティティが自分の形の影を落とすこと自体は、Vibrant Visuals 本体の機能です。**
ビデオ設定でオンにすれば、列車も船も Mob も形どおりの影を落とします。
影の細かさはビデオ設定の影の品質で決まり、リソースパックからは変えられません。

リソースパックから変えられるのは影の**スタイル**だけです（`shadows/global.json`）。

| 項目 | このパック | 意味 |
|---|---|---|
| `shadow_style` | `soft_shadows` | 輪郭の柔らかい影。`blocky_shadows` にするとドット絵風の角ばった影になる |
| `texel_size` | 16 | `blocky_shadows` のとき、影をどの細かさのマス目にそろえるか。`soft_shadows` では使われない |

> 以前のこのパックでは `texel_size` を「シャドウマップの解像度」と説明していましたが、
> 誤りでした。影の細かさを上げる効果はありません。

## manifest の `capabilities`

```json
"capabilities": ["pbr"]
```

**この1行が無いと、`lighting` や `atmospherics` などのファイルはすべて無視されます。**
テクスチャの差し替えだけは効くので「パックは入っているのに見た目が変わらない」という
分かりにくい壊れ方をします。`tools/check_bedrock.py` はこれを検出します。

## 列車などのアドオンを金属っぽく見せる

Vibrant Visuals は PBR（金属感・粗さ・発光）に対応しています。アドオンのテクスチャに
**テクスチャセット**を足すと、塗装された車体らしい艶が出ます。

一番手軽なのは、パック全体のエンティティ既定値を変えることです
（`pbr/global.json` の `actors`）。数値は `[金属度, 発光, 粗さ, 表面下散乱]` で、
粗さを下げるほど艶が出ます（このパックは 190、バニラは 255）。広く控えめなハイライトだけの
しっとりした艶です。これ以上なめらかにしないのは、Vibrant Visuals はエンティティの内側で
空をさえぎらないためです。列車の車内では全ての面が空に照らされ、空を映すので、150 では
車内が青白くかすみました。テクスチャセットの無い Mob もこの値になりますが、Mojang 自身の
Mob の質感（スティーブで 154〜255）の中ほどなので自然に見えます。

個別に作り込むなら、アドオンの `textures/entity/` にあるテクスチャ `my_train.png`
に対して、同じ場所に `my_train.texture_set.json` を置きます。

```json
{
  "format_version": "1.21.30",
  "minecraft:texture_set": {
    "color": "my_train",
    "metalness_emissive_roughness_subsurface": "my_train_mers"
  }
}
```

`my_train_mers.png` は色テクスチャと同じ大きさの画像で、各チャンネルが次を表します。

| チャンネル | 意味 | 車体の目安 |
|---|---|---|
| R | 金属度 | 塗装 0、無塗装ステンレス 255 |
| G | 発光 | 行先表示・前照灯 200〜255、他 0 |
| B | 粗さ | 磨かれた車体 40〜70、艶消し 180〜 |
| A | 表面下散乱 | 通常 0 |

テクスチャセットが参照する画像は、**テクスチャセットと同じパックの同じフォルダ**に
無いと無視されます（別のパックにある画像は使えません）。

### MTC の列車から自動で作る（`tools/build_train_pbr.py`）

MTC の列車アドオンなら、テクスチャセットを自動で作れます。

```bash
python3 tools/build_train_pbr.py 列車.mcaddon --out build/train_pbr --preview build/train_preview
```

モデルの全ての面の UV をテクスチャに重ねて、どのピクセルがどの部品（ボーン）に使われて
いるかを調べ、ボーン名（`tsurikawa` 吊り手の棒・`turikawa` 吊り革・`nidana` 網棚・
`sodesikiri` 袖仕切り・`yukasita` 床下・`maku` 行先・`lcd`・`mascon`・`panta` など、MTC や
TBTK テンプレートの命名）と、MTC の列車のアルファの決まり（255 が外側、127 が車内、
それより低いと照明、0 が窓の抜き）、色から材質を決めます。車体のステンレスは艶のある銀、
帯は艶のあるフィルム、前面の黒はガラスのような艶、車内の壁は化粧板、床はゴム、座席は
モケット、行先・LCD・計器の灯・前照灯・天井の照明は発光、凹凸は付けません（RTX 風の
すっきりした面）。車体や手すりは金属にしすぎると昼に周りを映して灰色になり、ぎらつくので、拡散を主にして
金属の艶を薄く乗せる程度にしています。車内はアドオン側が面を半分自発光させて明るく見せて
いますが、Vibrant Visuals ではそれだと陰影が消えるので、ごく弱い発光だけにして照明器具を
光らせます。

出力は**アドオンの上に置く別のリソースパック**で、アドオン自体は書き換えません。
テクスチャセットと同じパックに画像が要るため、元の色テクスチャのコピーが入ります。色はそのままで、
車内を半分自発光させるアルファの指定だけを外しています（Vibrant Visuals では車内が真っ白に
のっぺりするため。`--keep-glow` で元のまま）。
元のアドオンと同じく**個人利用のみ**で、配布はしないでください。`--preview` を付けると、
部品の判定結果と材質（赤＝発光、緑＝艶、青＝金属）を色分けした画像も出ます。

## メッシュの部品をなめらかに（`tools/smooth_meshes.py`）

統合版のモデルは箱（キューブ）の組み合わせで、アドオンによっては自由な形のメッシュ
（`poly_mesh`）を使った部品があります。メッシュは多角形どうしで頂点を共有していますが、
**従来の描画では、陰影はモデルファイルに書かれた法線のとおりに付きます**。多くの書き出し
ツールは多角形ごとの平らな法線を書くので、丸い部品でも辺ごとに折り目が出ます。このツールは
その場合のためのものです。なお、法線がすでになめらかなのに Vibrant Visuals でだけ折り目が
出るモデルもあり、その原因はモデルではなく Vibrant Visuals の描画側にあるため、この
ツールでは直りません（原因を確認中）。
Vibrant Visuals のシェーダーはリソースパックから変えられないため、直せるのはモデルファイル
だけです（バニラのモデルはすべて箱で、メッシュはありません）。

```bash
python3 tools/smooth_meshes.py アドオン.mcaddon --out build/smooth_meshes
```

メッシュの各頂点の法線を、その頂点を共有する多角形の法線の平均（面積で重み付け）に
書き換え、共有された辺で陰影が途切れないようにします。`--angle`（初期値 80°）より鋭い
折れ目は残すので、円柱のふたのような本当の角は角のまま、曲面だけがなめらかになります
（`--angle 180` で頂点を共有するところはすべてなめらかに）。箱の部品は一切変えません。
出力はメッシュを含むモデルファイルだけの**アドオンの上に置く別のリソースパック**で、同じ
パスと識別子でアドオンのモデルを置き換えます。アドオン自体は書き換えません。個人利用のみ。

## 雨のままワールドを開き直すと空が晴れている（`weather_sync/`）

雨の降っているワールドを閉じて開き直すと、雨は降っているのに空は晴れのまま（日差しも
強いまま）になります。これはゲーム側の不具合で、天気が次に変わるまで直りません。
リソースパックは天気に触れられないので、**別のビヘイビアーパック「VYSE Weather Sync」**
（`VYSE-Weather-Sync-*.mcpack`）を用意しています。ワールドの設定 → ビヘイビアーパックで
有効にすると、ワールドに入って 3 秒後、雨（雷雨）なら一瞬だけ雨を止めてすぐ降らせ直し、
空を雨の空に戻します。雨の残り時間はゲームが新しく決め直します。ブロックや設定は何も
変えません。

## 調整したいとき

設定ファイルは `tools/generate_bedrock.py` から生成しています。数値はこのスクリプトの
先頭近くにまとまっているので、そこを変えて再生成するのが確実です
（JSON を直接編集しても動きますが、再生成すると上書きされます）。

| やりたいこと | `tools/generate_bedrock.py` の場所 |
|---|---|
| 日差しを強く／弱く | `SUN_ILLUMINANCE` |
| 夕焼けの色 | `SUN_COLOR`（光の色）と `sky_tables` の `golden` / `sunset` など、`DUSK_ZENITH`（空の色） |
| 空をもっと青く | `DAY_ZENITH`（天頂の色）と `RAYLEIGH` |
| 太陽のまわりの光の輪 | `SUN_MIE`（明るさ）と `SUN_GLARE`（大きいほど太陽の近くに集まる） |
| 影を暗く／明るく | `SKY_INTENSITY`（空からの光。0.1〜1.0、下げるほど影が濃い） |
| 洞窟の暗さ | `AMBIENT_ILLUMINANCE` |
| 夜の明るさ | `MOON_ILLUMINANCE`（深夜は 0.400〜0.600 の値）、`SKY_INTENSITY` の夜の値、`DEEP_NIGHT_ZENITH`（深夜の空の色） |
| 霞を薄く／濃く | `HAZE` の `clear` などの最初の数値（濃さ） |
| 光芒の見え方 | `HAZE` の3番目の数値（前方散乱。1 に近いほど太陽の方を向いたときだけ強く、下げるほど横から見ても見える） |
| 画の系統 | `TONE_MAP`（`aces` / `generic` / `hable` など） |
| 色を落ち着かせる | `BASE_GRADE` の `saturation` / `contrast` |
| 水の波を止める | `WATER` の `waves.enabled` を `False` |
| 水の色をバイオームに寄せる | `WATER` の `biome_water_color_contribution`（0〜1） |
| ブロックの光の色 | `LIGHT_COLORS` |
| 雲の明るさ・夕焼けの染まり方 | `CLOUD_CUBEMAP` の `ambient_light_illuminance`（明るさ）と `directional_light_contribution`（日の色の強さ） |
| 雲の量 | `tools/draw_sky.py` の `cloud_density` の `n + 0.03`（この数値を上げると雲が増える） |
| 空の画像の貼られ方（雲の位置や大きさがずれるとき） | `tools/draw_sky.py` の `EYE_BELOW_CENTRE`（目が立方体の中心からどれだけ下にあるか） |
| 太陽の軌道の傾き | `ORBITAL_OFFSET`（度） |

```bash
python3 tools/generate_bedrock.py --vanilla <bedrock-samples>/resource_pack
python3 tools/check_bedrock.py --vanilla <bedrock-samples>/resource_pack
```

キー名を打ち間違えたり範囲外の値を入れたりしても Minecraft は何も言わずに無視するので、
このチェックを通してから入れてください。

# Java版

Iris / OptiFine 用の遅延レンダリングシェーダーパックです。**エンティティがモデル
そのものの形の影を落とす**ことを中心に組んであります（統合版と違い、影の仕組み自体を
シェーダー側で書いています）。

- 必要環境: **Iris 1.6 以降**（推奨）または **OptiFine H9 以降** / Minecraft 1.16.5 〜 1.21.x
- 導入: `VibrantVisuals-Java-*.zip` を `.minecraft/shaderpacks/` に置く
- 詳細: [docs/ENTITY_SHADOWS.md](docs/ENTITY_SHADOWS.md) / [docs/PIPELINE.md](docs/PIPELINE.md)

設定画面は日本語表示に対応しています。プロファイルは `最低` / `低` / `中` / `高` / `最高`。
列車のような長い編成では `高` を選んでから、`影の描画距離` と `エンティティの影範囲` を
上げてください。

## 開発

統合版の生成・検証には Mojang のバニラリソースパック
（[Mojang/bedrock-samples](https://github.com/Mojang/bedrock-samples) の `resource_pack`）と、
Python の Pillow / numpy が要ります。

```bash
git clone --depth 1 https://github.com/Mojang/bedrock-samples
pip install pillow numpy
V=bedrock-samples/resource_pack

python3 tools/generate_bedrock.py --vanilla $V   # 設定ファイルを生成（bedrock/ と diagnostic/）
python3 tools/draw_sky.py                        # 丸い太陽と月、雲のスカイボックスを描く（数分かかる）
python3 tools/draw_water.py                      # 模様のない水のテクスチャ
python3 tools/check_bedrock.py --vanilla $V      # 統合版パックの検証（キー名・値の範囲・全バイオーム網羅）
tools/package.sh --vanilla $V                    # 配布ファイルを生成（PBR 追加パックを含む）

python3 tools/validate_shaders.py     # Java版 GLSL を全52ステージ×4構成でコンパイル
python3 tools/check_options.py        # Java版の設定項目の整合性
```

`glslangValidator` が PATH に無い場合は `--glslang <path>` を渡してください
（[ビルド済みバイナリ](https://github.com/KhronosGroup/glslang/releases)）。
